# SimLab Studio 使用说明

Studio 将论文案例一的串联制造线包装为本机应用。用户可以编辑初始模型、观看仿真过程、用自然语言生成下一版方案，并通过多次重复实验比较效果。EXE 桌面版的启动、数据位置及系统要求见 [桌面版使用说明](desktop.md)；以下启动命令面向浏览器开发模式。

## 启动

需要 Python 3.11 或更高版本。在项目根目录运行：

```powershell
python -m pip install -e ".[studio]"
python -m simlab.cli studio --open-browser
```

Windows 可以双击 `start_studio.cmd`，它会在仓库下创建 `.venv`，首次启动时安装应用依赖，再打开浏览器。首次安装需要网络；不用 LLM 时，已安装的仿真和编辑功能可以离线运行。关闭命令行窗口会停止应用。

默认地址为 `http://127.0.0.1:8765`。端口被占用时可使用 `--port 8766`；会话默认保存在 `outputs/studio`，也可以用 `--output` 指定目录。当前应用仅监听本机，不包含远程多用户登录功能。

## 完成一次实验

1. **建立初始模型。** 左侧默认载入案例一的四台设备、三个缓冲区、30 天仿真期、1 天预热和 25 次重复。修改设备周期、可用率、维修时间、功率、班次或实验设置后，保存为新版本。模型配置也可以导入或导出为 JSON。
2. **观看动态过程。** 启动仿真预览。计算完成后，播放、暂停、拖动时间轴或改变速度，观察设备加工、缺料、堵塞、故障和停班状态，以及缓冲区占用。
3. **提出自然语言目标。** 配置 LLM 后输入例如“保持缓冲容量不变，将第一台设备的可用率改成 90%，其余参数不变”。应用把当前配置、约束和可用实验结果交给 LLM，将通过校验的修改保存为新版本，并生成新回放。
4. **评估完整方案。** 对需要比较的版本执行统计评估。它按该版本的完整时长和重复次数运行，显示产出率、平均在制品、单位能耗的均值及置信区间。
5. **保留或恢复方案。** 从历史中查看修改内容，恢复旧模型时会创建一个新版本；之前的记录仍可查看。
6. **导出结果。** 下载实验包，保存配置、版本记录、仿真数据和报告。尚未完成统计评估的版本不能据预览结果宣称已经得到最终性能结论。

## 接入和切换 AI 模型

点击顶部的“模型接入”，可以新增、编辑和保存多套 API 与模型配置。每套配置都有独立的名称、API 地址、模型名称、接口格式和密钥，例如一套连接 OpenAI 的 GPT 模型，另一套连接兼容服务。这里的 Agent 指提供调整建议的 AI 模型，生产线的参数校验规则保持一致。

填写后选择“保存并启用”。随后可以直接在右侧助手面板的“当前 AI 模型”中切换已保存配置，无需重新填写地址和模型。播放、暂停或查看仿真时都可以切换，已有模型版本和实验结果不会因此改变。配置选择在本机应用内共享。

**切换从下一次提示词请求生效。** 已经发送的请求使用发送时的 API 与模型完成处理，不会中途改发到另一个服务。每次 AI 回复及其生成版本记录实际使用的配置名称、模型和接口，便于比较不同模型的建议。

“自动选择”在官方 OpenAI 地址使用 Responses，在其他兼容地址使用 Chat Completions JSON。也可以手动指定 Responses 或 Chat Completions，以匹配支持相应接口的代理服务。API 地址应填写服务提供商的 API Base URL；模型名称应使用该服务账户实际可用的名称，不能用 ChatGPT 网页地址代替 API。默认 OpenAI 模型为支持结构化输出的 `gpt-4.1-mini`，可自行更改。接口依据 [OpenAI 结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)；模型能力见 [官方模型说明](https://developers.openai.com/api/docs/models/gpt-4.1-mini)。

配置名称、地址、模型和接口格式保存在本机的 `outputs/studio/ai_profiles.json`；更改 `--output` 时该文件位于指定目录。可以删除不再使用的配置，删除当前配置前须先切换到另一套。

各配置的密钥默认仅保留在当前服务进程内存中。Windows 测试版可选“在本机加密保存密钥”：用户勾选并保存后，将 DPAPI 密文写入 `ai_profiles.json`，重启时解密恢复。明文密钥不会写入配置文件；明文和密文都不返回给浏览器、不保存到实验会话或导出包。编辑时密钥留空会保留同一 API 地址下的现有密钥；更换地址后须重新输入，旧密钥及磁盘副本不会用于新服务。非 Windows 系统保留仅本次运行模式，已有不可读密文不会自动删除。详见 [密钥保存说明](credential-storage.md)。

环境变量仍可为匹配且没有已保存密钥的默认连接提供密钥（不自动加密保存）：

```powershell
$env:OPENAI_API_KEY = '<填写自己的密钥>'
$env:SIMLAB_OPENAI_MODEL = '<账户中可用的模型名称>'
python -m simlab.cli studio --open-browser
```

使用兼容服务时，也可以设置 `SIMLAB_OPENAI_BASE_URL`。不要将真实密钥写入 Git 仓库。应用不会自动读取 `.env` 文件；使用环境变量时应在启动进程的终端中设置。

没有 API 密钥时，模型编辑、预览、评估、版本恢复和导出仍然可用；自然语言调整会提示配置服务，应用不会用规则输出冒充 LLM 响应。

LLM 返回的是结构化参数修改。应用逐项检查字段、单位、取值范围、模型完整性和当前实验约束，通过后自动应用到新的仿真版本。LLM 的预期改善是一项待验证的建议，实际效果以运行结果为准。第一版每条提示词产生一轮修改，用户可继续对话形成多轮实验。

## 论文模式与自定义模式

**论文模式**固定案例一的设备顺序和三个中间缓冲区的容量。设备参数可以调整，但增加缓冲容量会被拒绝。完整论文参数及假设见 [案例一说明](paper_case_a.md)。

**自定义模式**允许探索其他合法的缓冲容量及模型配置，结果标记为自定义实验。这些方案不能被误认为满足论文原始约束。

应用对单次任务的时长、重复次数、设备数量及估计工作量设置上限；越界会显示错误，用户可以减少实验规模后重新运行。

## 动画、时间与统计含义

预览使用真实 SimPy 状态的定时快照，默认从仿真起点开始、最多覆盖“预热期加一天”的时间段。默认设置的预览不包含周末，完整班次影响需要通过全时长评估查看。动画界面回放这些快照，设备间的视觉运动用于解释状态变化，不能代替逐件、逐事件的完整轨迹。

仿真时间、后台计算耗时和动画播放时间彼此独立。拖动时间轴或加快播放速度不会改变模型计算。预览通常只是一轮运行；最终评估使用完整仿真期和多个独立随机重复。不同版本保持相同种子时使用共同随机数，以减少比较中的随机噪声。

产出率按扣除预热后的日历小时计算，包含计划停产时间；平均在制品包括设备持有的工件和中间缓冲区中的工件；单位产品能耗是同一统计窗口内能耗除以完成件数。预热尚未结束、统计窗口为零或没有完成件时，部分指标显示为空。实时快照的指标只计算到该时刻，不包含未来数据。

原料按需持续补充，原料仓和成品不计入生产线在制品。可用率通过工作时间上的指数故障间隔及指数维修时长实现。其余建模假设与案例一实现保持一致。

## 第一版的边界

在观看过程中提出调整后，应用保存新配置并从初始状态重新仿真。它不会保留上一轮加工到一半的工件并在同一仿真时刻修改参数续跑。

当前界面围绕串联制造线的二维展示，未提供任意流程的拖拽建模、写实三维场景或自动修改任意 Python 代码。动画是否流畅与模型是否符合工厂真实情况是不同问题；工程应用仍应以真实生产数据校准模型。

## 开发验证

```powershell
python -m pip install -e ".[dev]"
python -m pytest
```

测试包含分段与整轮仿真的结果一致性、物料守恒、统计窗口、版本恢复、模型约束、结构化 AI 修改、会话持久化和导出。LLM 调用测试使用注入的模拟客户端，不会消耗真实 API 额度。

可选浏览器测试需要 Node.js、`playwright` 和 Microsoft Edge。安装 Playwright 后，保持正常 Studio 运行，再执行 `node tools/check_studio_browser.cjs`，它会新建短时实验，验证编辑、动画播放与暂停、评估、导出、版本恢复、JSON 导入和移动端布局。结果保存在 `outputs/studio_qa`。

验证 AI 界面流程时，在另一个终端运行 `python tests/studio_browser_fixture.py`，将 `STUDIO_TEST_URL` 设为 `http://127.0.0.1:8876`，再执行 `node tools/check_studio_ai_browser.cjs` 或 `node tools/check_studio_profiles_browser.cjs`。后者覆盖多套模型配置、切换、回放保留和历史模型来源。该服务明确注入固定测试响应，脚本会先检查测试服务标记；不调用真实 LLM，不用于实际建模。
