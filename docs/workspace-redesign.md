# 仿真工作台设计与交互

本分支 `frontend/simulation-workspace` 将仿真画面作为主要工作区域，把输入模型编辑与结果评估放到按需打开的窗口中，右侧集中动态指标与运行助手。原有模型、仿真、AI 参数校验、持久化和导出接口继续使用。

工作台最初在测试分支开发，现随 v1.1.0 正式合并到 `main`。后续开发覆盖更新同一份工作版本；第一版发布记录继续保留。界面预览、设备扩展和 AI 修复不再各存一个成品目录。

## 工作流程

### 1. 检查输入模型

点击“编辑模型”或侧边导航“模型”，打开输入模型窗口。设备参数、缓冲容量与转运时间、论文/自定义模式、每周停产时段、时长、预热、重复次数、种子、JSON 导入导出均保留。修改后点击“应用修改并预览”；已有模型无需修改时，直接点击“运行预览”。

打开或关闭模型窗口不会替用户提交修改。未应用的修改继续标记为草稿，发送 AI 指令前需先应用。

输入模型和运行结果窗口都可点击外侧遮罩返回主界面，关闭按钮和 Esc 仍可使用。关闭后再打开输入模型保留本次应用进程中的草稿；不会自动保存、提交或重新运行。点击窗口内空白、滚动或从窗口内拖动到外侧不关闭窗口，遮罩点击不会穿透触发主界面按钮。评估任务在窗口关闭后继续执行。

#### 添加设备与缓冲容器

在“加工设备”标题下点击“添加设备与容器”，选择产线起点、任意设备之后或产线末端，填写名称、加工时间、可用率、维修时间、功率，以及配套容器的容量和转运时间。新增设备的参数预填自产线末台设备，需要按实际设备核对。确认后自动切换到自定义实验，内容先写入输入草稿；取消添加不会改动模型。

现有串联引擎要求 **N 台设备对应 N−1 个中间容器**。此入口添加的是设备与容器组合，最多 12 台设备，容器容量为 1–10000 件；不表示支持独立储罐、分支连接或任意流程图。插入中间位置时保留原有容器并为新增边添加容器；插入末端时容器位于新增设备之前。对话框会展示新增连接。

自定义模式下可编辑设备和容器名称，名称在各自类别内必须唯一。设备卡片内提供“移除设备与配套容器”，确认窗口说明具体移除对象；至少保留一台设备。论文模式保留原名称、结构和容量约束，添加操作明确切换为自定义模式。

添加、移除与重命名不会立即影响正在回放的已保存方案。点击“应用修改并预览”后，经原有后端校验保存新版本并重新仿真，历史版本继续保留。拓扑编辑验证使用 `tools/check_topology_browser.cjs`，连接同一注入 AI 测试服务；覆盖新增位置、取消、重名、维修参数、草稿保留、数量上下限、真实 12 设备预览和重复评估、导出及恢复。

### 2. 全屏观察与随时暂停

用户点击运行预览时进入全屏工作区，并通过原有接口请求预览。中央画布显示设备、缓冲区与产出状态，右侧显示产出率、平均在制品、单位能耗及其变化曲线；画布下方补充完成产品数、加工设备数和缓冲区在制品。

播放过程中可以暂停、继续、从头回放、拖动进度和改变倍速。退出全屏不会删除模型或结果。桌面宿主不支持 Fullscreen API 时，工作区占满应用视口；这与操作系统级的窗口全屏不是同一能力。

### 3. 与运行助手协作

运行助手右上角提供“放大”按钮。大窗口使用接近整个应用高度的对话区和 15px 正文字号，仍保留当前模型切换、管理接入、建议提示词和发送入口。点击“收起”、窗口外空白或按 Esc 可回到原侧栏；再次展开继续查看同一段对话。

两种视图共用原来的对话与输入控件，切换时保留未发送文本、选定模型和阅读位置。放大或收起不会发起 AI 请求、暂停仿真或取消正在等待的回复；只有发送调整指令时才沿用原有暂停与模型校验流程。

| 操作 | 回放与模型行为 |
| --- | --- |
| 在输入框打字、选择建议提示词 | 继续回放，不发出 AI 请求 |
| 切换右侧 AI 模型配置 | 继续回放；下一条请求使用新配置 |
| 发送通过本地检查的有效指令 | 立即暂停回放，并把指令交给发送时选定的 AI 配置 |
| AI 请求进行中 | 显示进度；旧回放的播放、重播和拖动暂时锁定，避免修改期间混淆版本 |
| AI 修改通过原有校验 | 创建并保存新版本，用原有预览 API 从初始状态重新运行，自动播放新回放 |
| AI 未提出有效修改或请求失败 | 保留原模型与回放，显示结果或错误；用户可手动继续播放 |

请求已经发送后再切换 AI 配置，不改变当前请求的服务或模型。会话消息与模型版本继续记录实际使用的配置，便于追溯。没有有效 API 配置或模型仍有未应用草稿时，会先提示处理条件，不启动调整请求。

助手只有在用户发送指令时调用 LLM。页面浏览、回放结束、生成评估文字或导出报告不会自动发起额外的 AI 调用。

### 4. 完成后的最终指标与方案评估

回放自然播放到结尾时，页面为当前版本调用已有完整评估接口。已完成或正在运行的该版本评估会被复用，同一版本不会因反复播放结尾而重复提交自动评估；手动“评估当前方案”仍然可用。仅拖动滑块到结尾不等于自然播放完成。

评估按模型设置的完整时长、预热和重复次数执行。结束后显示结果就绪提示，不自动打开弹窗或转移输入焦点。点击“查看最终结果”或侧边“评估”，可以查看：

- 产出率、平均在制品、单位产品能耗的均值及置信区间；数据不足时明确显示无法估计区间。
- 当前模型的规模、约束模式、方案说明和具体参数修改。
- 评估时长、预热、重复次数、随机种子与置信水平一致的历史对照；有对照时描述观测均值变化，没有时说明尚无可比结果。
- 原有方案版本表、修改记录、恢复按钮与手动评估入口。

报告中的对照描述不等于显著性检验，也不证明方案最优。评估文字由保存的参数和真实结果生成；用户应结合指标取舍与置信区间判断方案。

新增“导出结果报告”可单独保存 HTML，包含最终指标、方案解读与输入配置。原有“导出实验”继续保存 ZIP，保留完整版本记录、仿真数据和原报告。两种导出均不包含 API 密钥。

### 历史方案详情

在“运行结果与评估 → 方案版本与对比”中点击任一版本的“详情”，使用同一个完整评估窗口显示该版本的三项最终指标、置信区间、方案说明、全部修改记录及可比历史对照。窗口上方标明查看版本，支持下拉切换及“返回当前方案”；左侧“评估”入口重新打开时始终显示当前方案。

历史详情继续保留创建时间、AI 模型来源和完整模型 JSON。导出结果报告使用正在查看的版本及其配置，不会混用当前方案。未做完整评估或历史结果无法读取时，明确显示状态，禁用报告导出；如需重新评估历史模型，可沿用“恢复”操作创建新方案后运行。

查看、切换和关闭历史详情不会修改当前模型、暂停回放、创建运行任务或调用 AI。后台结果更新时保持选中的历史版本。运行 `node tools/check_history_results_browser.cjs` 可在隔离测试服务上验证版本对应关系、报告、回放和窗口布局。

## 真实的运行边界

预览是实际 SimPy 仿真状态的定时采样回放。暂停控制的是浏览器中的回放进度，**不是冻结后台正在计算的 SimPy 进程**。仿真计算耗时、模拟时钟与动画播放时间相互独立。

AI 调整创建新模型并从初始状态重跑，**不支持把旧模型运行到一半的工件、设备状态或事件队列迁移到新模型继续运行**。页面没有向原引擎添加实时检查点、任务取消或状态迁移接口。

预览可能只覆盖完整时长的一部分，默认最多覆盖预热期加一天；页面继续展示实际预览范围。旁侧指标是当前采样时刻的预热后累计统计，不能代替完整实验。正式完整评估使用原有重复实验 API，结果在评估窗口单列。

改版仍为串联制造线的二维展示。没有引入任意流程拖拽建模、写实三维场景或让 AI 直接重写 Python 程序的能力。模型定义及指标口径详见 [仿真说明](studio.md) 和 [案例一参数与假设](paper_case_a.md)。

## 开发运行与验证

在本分支根目录使用 Python 3.11+。建议在独立虚拟环境中安装，并使用独立数据目录体验改版，避免与正在运行的第一版共用会话数据。

```powershell
git switch frontend/simulation-workspace
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[desktop,dev]"

# 原生桌面窗口，后台服务自动启动
.venv\Scripts\python.exe desktop_entry.py --data-dir outputs/workspace-desktop

# 或在浏览器中开发预览，使用单独端口与输出目录
.venv\Scripts\python.exe -m simlab.cli studio --port 8877 --output outputs/workspace-preview
```

浏览器验证需要 Node.js、Playwright 和 Microsoft Edge；测试脚本默认使用 Edge，可通过 `PLAYWRIGHT_CHANNEL` 指定其他已安装的兼容通道。在一个终端启动专用测试服务：

```powershell
.venv\Scripts\python.exe tests/studio_browser_fixture.py
```

另一个终端安装浏览器测试依赖并运行：

```powershell
npm install --no-save --package-lock=false playwright
$env:STUDIO_TEST_URL = "http://127.0.0.1:8876"
node tools/check_workspace_browser.cjs
```

`STUDIO_TEST_URL` 必须显式指定。脚本首先检查 `/fixture-health` 的注入测试标记，拒绝把调整测试发送到正常模型服务。测试使用固定响应的注入 AI，不调用外部 LLM，也不消耗付费 API 额度。该测试服务只用于验证界面，不能用于实际建模。

检查覆盖桌面和最小窗口布局、输入模型、全屏与退出、真实采样指标、暂停与进度、输入/建议/模型选择不暂停、发送时立即暂停、模型来源快照、调整后自动播放、失败后继续、自然结束仅请求一次评估、独立报告、原 ZIP、会话恢复、历史版本恢复和 JSON 导入。截图与检查记录保存在忽略提交的 `outputs/workspace_qa`。

核心回归测试仍可使用：

```powershell
.venv\Scripts\python.exe -m pytest
```

本分支没有修改打包脚本或第一版发行文件。构建测试版先输出到固定暂存目录 `dist/test-edition`，验证成功后覆盖交付目录 `SimPy Lab Studio 测试版/SimPy Lab Studio.exe`，不另建以功能命名的版本目录：

```powershell
.venv\Scripts\python.exe -m pip install -e ".[desktop,desktop-build,dev]"
.venv\Scripts\python.exe -c "from tools.build_desktop import licenses; licenses()"
.venv\Scripts\python.exe -m PyInstaller --noconfirm --distpath dist/test-edition --workpath build/test-edition desktop.spec
```

测试版 EXE 沿用原有桌面宿主、图标和自动服务生命周期。原宿主采用单实例机制，因此打开另一版前需先关闭正在运行的版本；实验数据格式仍然兼容。v1.1.0 发布时统一更新了界面、桌面版本常量、EXE 资源和安装程序的版本号，单实例逻辑保持不变。
