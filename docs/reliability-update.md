# v1.2 测试分支可靠性更新

依据 2026-09-16 评估，先落实草稿保护、AI 修改预览、请求控制及基本工程检查。正式 v1.2.0 标签、安装包和历史源码包保留；此文对应滚动测试版，不代表新正式版本已发布。

## 草稿保护

图形与参数表冲突时保留原图形、节点和撤销记录，禁止直接覆盖当前输入。可选择“保留图形并合并当前实验设置”，或确认放弃草稿后重新载入。前者保留图形中的设备/容器参数与连接，使用当前输入的实验时长、种子等设置；仍须应用才会保存模型。

图形草稿、最多 80 步撤销/重做、参数表未填完的字段和未发送输入按实验保存在本机界面存储。刷新或重开时恢复；若基础版本变化，参数表提供恢复/放弃选项。清除 WebView/浏览器数据、换用户或本机服务端口变化会影响这类界面存储，仍应及时保存重要模型。API 密钥不进入草稿。

已完成仿真及对话仍由原实验存储保存。尚在计算的仿真被关闭打断后标记失败，需要重新运行；本轮不迁移 SimPy 事件队列。

## AI 修改预览与请求控制

发送目标后暂停回放，显示排队/生成状态及等待秒数。通过参数校验的方案展示修改前后值、所用模型和说明；只有点击“确认应用并预览”才创建版本。可以稍后查看或放弃。待确认方案存入实验，重启后仍需确认。当前版本发生变化时拒绝应用过期方案。

“取消请求”立即终止本地等待并阻止迟到回复应用；已经发出的服务商请求可能继续完成和计费。失败或取消后可手动重试。生成有 180 秒本地等待上限，保留原 SDK 的请求超时与一次重试。并发生成最多 2 项，总在途/排队最多 4 项；取消但尚未返回的服务商调用仍占计算槽位，避免反复取消导致线程无限增长。

重复提交同一请求标识不重复调用模型；重复确认同一方案不创建重复版本。应用时重新执行参数与论文约束校验。密钥在回复、请求记录及导出中脱敏。

网页使用新的 `/adjustments`、`/{id}/cancel` 和 `/{id}/apply` 工作流。旧 `/adjust` API 保留兼容原有本地集成的自动应用语义；它不属于新的网页确认流程。历史数据可继续打开。

## 评估与工程

完整评估在关键指标少于 30 次有效重复时增加小样本提示，报告同步包含提示。30 次只是提示阈值，不保证精度或显著性。仍使用原正态近似区间，未引入新的统计检验或生产数据校准。

包版本与桌面基线统一为 1.2.0，保留兼容包名 `simpy-kpi-lab`；滚动测试版与正式包通过交付目录和本更新说明区分。新增 Windows Python 3.11/3.13 CI：Ruff、Python 测试、85% 行覆盖率门槛、图形单元测试和隔离浏览器可靠性检查。CI 配置已写入；远端实际运行以推送后的 GitHub 状态为准。

本轮没有新增并行/返工产线、数字签名或自动更新，也未把未经验证的效果作为性能结论。后续需另行完成复杂引擎、统计校准以及 Windows 10/缺失 WebView2 的真机验证。
