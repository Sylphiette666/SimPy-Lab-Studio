# 论文案例一：四设备串联机加工生产线

本次修改依据 Schmitt 等论文 *LLM-driven discrete-event simulation: A generative AI framework for automated model generation, adaptation, and evaluation in manufacturing*（Journal of Manufacturing Systems 85, 2026, 642–661），DOI：[10.1016/j.jmsy.2026.02.015](https://doi.org/10.1016/j.jmsy.2026.02.015)。案例一对应原文 Case A，参数来自表 4、图 5、图 7、第 5.3 节和附录 C。

项目新增独立的制造线仿真引擎 `simlab.manufacturing` 及 `simlab case-a` 命令，复用原有随机种子派生与统计汇总能力。原有服务系统的 YAML、运行命令和审批 API 继续使用其原有模型。

## 对应论文的模型

```text
持续供料 → SV36262 → buffer1 → SV32173 → buffer2 → SV91991 → buffer3 → SV91989 → 成品
```

| 设备 | 周期时间（秒） | 可用率 | MTTR（秒） | 空闲功率（kW） | 加工功率（kW） |
|---|---:|---:|---:|---:|---:|
| SV36262 | 320 | 85% | 1409 | 10 | 50 |
| SV32173 | 290 | 85% | 718 | 10 | 50 |
| SV91991 | 134 | 98% | 6717 | 10 | 50 |
| SV91989 | 41 | 99% | 671 | 10 | 50 |

三个中间缓冲区的容量均为 5 件，转运延迟均为 10 秒。仿真总时长为 30 天，包含 1 天预热；每个场景独立重复 25 次。每周停产区间为周五 17:00 至周六 07:00、周六 17:00 至周日 07:00。

## 运行方式

在项目根目录完成 `python -m pip install -e .` 后运行：

```powershell
# 基准 + 两个符合当前 CPD 的独立改进方案，共 75 次仿真
python -m simlab.cli case-a

# 为对照论文，额外模拟违反 CPD 的 V1，共 100 次仿真
python -m simlab.cli case-a --include-infeasible-v1 --workers 2 --output outputs/case_a

# 小规模调试（不能替代 30 天、25 次的正式对照）
python -m simlab.cli case-a --days 2 --warmup-days 0.25 --reps 2 --seed 123 --output outputs/case_a_quick
```

等价入口为 `simlab case-a`。命令支持 `--days`（或 `--horizon-days`）、`--warmup-days`、`--replications`（或 `--reps`）、`--seed`、`--workers`、`--output`。默认基础种子为 20260909；相同配置和种子下，串行与多进程运行产生相同的重复实验记录。

结果目录包含：

- `results.json`：完整配置、模型假设、每次实验、指标定义、统计汇总、方案约束状态及瓶颈候选排序。
- `replications.csv`：每个场景每次重复的指标宽表。
- `summary.csv`：每个指标的均值、标准差、置信区间、有效样本数与缺失数。
- `comparison.md`：中文方案对照、CPD 检查和假设说明。

这个命令执行确定性的建模规则与随机仿真实验，无需调用外部 LLM。论文中的自然语言模型生成和评估流程仍可作为后续扩展；本次交付实现的是案例 A 的生产模型、独立方案调整、约束检查和实验比较，没有声称复现论文的全部智能体工作流。

## 方案与约束

| 方案 | 相对于基准的唯一变更 | 当前 CPD 状态 |
|---|---|---|
| baseline | 无 | 合规 |
| V1 | 三个中间缓冲区容量全部从 5 增至 10 | 违反保持原缓冲容量的约束，仅显式开启时模拟，始终排除在合规推荐之外 |
| V2 | SV36262 可用率从 85% 提高至 90% | 合规 |
| V3 | SV32173 可用率从 85% 提高至 90% | 合规 |

所有方案都从基准单独构造，不按 V1→V2→V3 累加变更。`validate_case_a_adaptation()` 检查原机器顺序、缓冲区顺序和容量；校验结果不等同于实际工厂的生产变更批准。论文另一条 CPD“压力机加工时间不得低于 60 秒”适用于含压力机的案例 B，不应错误套用到案例 A 的 41 秒设备。

原文有两处需注意：案例 A 正文提到“版本 1 和 4”，但图 7–10 只定义 V1–V3；表 5 将第一条建议简写为 BT1–2 的输入缓冲区，而图 7 明确写三个中间缓冲区。本实现以图 7 的明确参数操作为依据。译文保留这些原文表述并作注。

## 明确记录的实现假设

论文未给出全部运行语义或随机种子，以下选择均写入每份 `results.json` 的 `assumptions`，用于保证可复现性。

1. 时间单位统一为秒，时间零点为周一 00:00。统计窗口为 `[86400, 2592000)`，预热仅排除观测，不清空机器或缓冲区。默认观测时长为 29 个日历日。
2. 原料按需补足，不使首台设备缺料。原文原料区容量 1000 保留在配置中，但不显式生成 1000 个待加工实体；原料区及成品区不计入生产 WIP。源端物流供给能力不是本案例研究变量。
3. 缓冲区进入时即占用容量，10 秒在途延迟也占用该槽位；多件可同时处于转运中，延迟不会被串行累加。满缓冲区使上游完成加工的零件留在机器上，阻止其加工下一件。
4. 故障间隔和维修时长服从指数分布。平均故障前运行时间按 `MTTF = availability × MTTR / (1 − availability)` 推导。故障时钟累计实际加工时间，不累计空闲、阻塞或计划停机时间；因此这里的可用率是故障过程参数，并非加工时间占整个日历时间的比例。
5. 故障及计划停机均暂停当前零件加工，恢复后只完成剩余加工时间。维修按日历时间继续，可跨越计划停机。停机期间不开始新加工，也不进行新的缓冲入区／取件；已开始的转运延迟继续流逝，取件等待复产。
6. 加工状态使用 50 kW，其余状态（缺料、阻塞、维修及计划停机）均使用 10 kW。能耗按状态持续时间精确积分；这里未假设停机时完全断电。
7. TH 为统计窗口内完成件数除以统计窗口的日历小时数，包含计划停机时间。WIP 为机器和中间缓冲区内零件数量的时间加权平均，包含在途和加工后被阻塞的零件，不重复计数。
8. SEC 为同一统计窗口内能耗除以完成件数；零产出时为缺失值 `null`，不伪造为零或无穷。跨重复汇总 SEC 使用每次实验 SEC 的平均值。
9. 不同重复使用独立种子，各设备的故障和维修采用独立随机流；同一重复编号在各场景间使用共同随机数。统计汇总沿用项目现有的正态近似置信区间方法，报告均值不表示方案差异已经通过显著性检验。
10. 瓶颈候选按实际加工利用率排序，仅作为论文式瓶颈分析的输入代理指标。结果同时提供加工、缺料、阻塞、故障和停机状态比例，便于人工核验。

这些语义选择会影响与论文的数值差异，尤其是第三台机器较长维修时间引起的 WIP 波动。因此本实现是依据公开参数独立建立的模型，并未以修改参数的方式强行拟合作者结果。论文图 6 的 7.38 件/小时、4.47 件、14.2158 kWh/件仅作为外部参考保留。

## Python 调用

```python
from simlab.manufacturing import (
    case_a_config,
    run_manufacturing_study,
    save_manufacturing_study,
)

if __name__ == "__main__":  # Windows 多进程需要入口保护
    config = case_a_config(replications=25, base_seed=20260909)
    result = run_manufacturing_study(config, include_infeasible=True, workers=2)
    save_manufacturing_study(result, "outputs/case_a")
```

制造模型采用独立的严格 Pydantic 配置类 `ManufacturingConfig`、`MachineSpec`、`BufferSpec`、`WeeklyBreak`。如需实验性修改，可构造配置后通过 `ManufacturingConfig.model_validate()` 校验，并使用 `run_manufacturing_replication()` 进行单次仿真。制造配置不是原服务系统的 `ProjectConfig`，不应传给原有 `simlab run` 或审批会话接口。

## 本次运行与验证

使用默认 30 天、预热 1 天、种子 20260909、每场景 25 次重复，2 个工作进程运行四个方案，共 100 次仿真。详细结果已保存到 `outputs/case_a`。

| 方案 | TH（件/小时） | 平均 WIP（件） | SEC（kWh/件） |
|---|---:|---:|---:|
| baseline | 7.706609 | 4.139131 | 13.914306 |
| V1（不合规） | 7.875345 | 5.650607 | 13.802351 |
| V2 | 8.076552 | 4.595955 | 13.675428 |
| V3 | 7.872414 | 3.524653 | 13.804055 |

在本次运行中，V2 的产出率比基准高 4.80%，单位产品能耗低 1.72%，平均 WIP 高 11.04%；V3 的平均 WIP 低 14.85%，产出率高 2.15%。V2、V3 分别体现产出率与库存侧重点，方向与论文所述一致，但绝对数值并非逐项复现。基准瓶颈候选前三位为 SV36262、SV32173、SV91991。

新增测试涵盖手算产出和能耗、时间加权 WIP、缓冲容量及实体守恒、并行转运延迟、加工后阻塞、故障剩余工时恢复、跨周日历、跨停机维修、预热裁剪、零产出、种子复现、多进程一致性、CPD 拒绝及 CLI 输出。完整项目测试 129 项通过，修改范围内 Ruff 检查通过。用于验证的环境补装了项目已有可视化可选依赖 matplotlib；项目依赖声明未增加新要求。
